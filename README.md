# Сравнение моделей HuggingFace для анализа тональности обращений

Продолжение темы диплома («AI-агент для анализа доходов и расходов»):
задача — классификация тональности обращений пользователя к финансовому
боту (например, чтобы определять, расстроен ли пользователь ростом
расходов, и приоритизировать ответ). Сравниваем 3 модели с HuggingFace Hub
и облачную модель через OpenRouter.

> Код, прогоны и выводы — с помощью ИИ-ассистента Claude Code; постановка задачи, ключевые решения и приёмка — мои.
> Подробнее — в [указателе по всем ДЗ](https://github.com/isergeevych/fin-assistant-diploma/blob/master/SUBMISSION.md#как-выполнена-работа).

## Шаг 0. Установка

```powershell
python -m pip install -r requirements.txt
```

`torch` и `transformers` весят прилично (~1-2 ГБ) — установка может занять
время. Для облачного сравнения (шаг 4) нужен ключ OpenRouter — см. README
прошлого проекта `model_selection_homework` или https://openrouter.ai/keys.

## Шаг 1. Задача

Выбрана **классификация тональности** — 3 класса: `positive` / `negative` /
`neutral`. Тестовые примеры — в `eval_examples.py` (12 обращений на тему
использования финансового бота).

## Шаг 2. Поиск моделей на HuggingFace Hub

```powershell
python find_models.py
```

Скрипт ищет кандидатов через `HfApi.list_models()` (задача
`text-classification`, язык `ru`, сортировка по скачиваниям) и печатает
ссылки на карточки моделей. Дальше — вручную:
1. Откройте карточки 3 моделей по ссылкам.
2. Прочитайте Model Card: на чём обучена, какие метки классов возвращает
   (это понадобится для `LABEL_MAP` в шаге 3).
3. Проверьте лицензию (поле `license` на странице модели) — для учебного
   проекта подойдёт почти любая, но обратите внимание, если лицензия
   запрещает коммерческое использование (`cc-by-nc-*`) — для дипломного
   продукта это может быть ограничением, стоит упомянуть в выводах.

## Шаг 3. Бенчмарк локальных моделей

Впишите 3 выбранных ID моделей и их `LABEL_MAP` (соответствие сырых меток
модели трём каноническим: `positive`/`negative`/`neutral`) в
`benchmark_local.py`, затем:

```powershell
python benchmark_local.py
```

Прогонит каждую модель через `transformers.pipeline("text-classification", ...)`
на всех 12 примерах, замерит время инференса и посчитает accuracy.
Результат — в `local_benchmark_summary.json`.

## Шаг 4. Сравнение с облачным API

```powershell
$env:OPENROUTER_API_KEY = "sk-or-ваш-ключ"
python benchmark_cloud.py
```

Тот же набор из 12 примеров и те же метрики (accuracy, время ответа), но
через облачную модель OpenRouter (`CLOUD_MODEL` в файле — проверьте
актуальный бесплатный список на https://openrouter.ai/models?max_price=0).
Результат — в `cloud_benchmark_summary.json`.

## Шаг 5. Gradio-демо

Впишите ID модели-победителя (по итогам шагов 3-4) в `BEST_MODEL` в
`gradio_demo.py`, затем:

```powershell
python gradio_demo.py
```

В консоли появится публичная ссылка `https://xxxxx.gradio.live` (живёт 72
часа благодаря `share=True`) — её и нужно прислать/показать. Для постоянной
ссылки — задеплойте на HuggingFace Spaces (создать Space с Gradio SDK,
скопировать файл как `app.py`).

## Результаты (прогон 2026-10-12)

12 обращений (по 4 на класс), одни и те же метрики. Локальные модели — CPU, время после прогрева;
облако — OpenRouter, время включает сеть.

| Модель | Где | Параметров | Accuracy | Время на пример | Лицензия |
|---|---|---|---|---|---|
| seara/rubert-base-cased-russian-sentiment | локально | 178 M | 66,7 % | 12,8 мс | MIT |
| cointegrated/rubert-tiny-sentiment-balanced | локально | 12 M | 75,0 % | 1,7 мс | не указана |
| **mxlcw/rubert-tiny2-russian-financial-sentiment** | локально | 29 M | **83,3 %** | **1,4 мс** | MIT |
| google/gemma-4-31b-it | облако | 31 B | 91,7 % | 666 мс | Gemma ToU |
| deepseek/deepseek-chat | облако | — | 91,7 % | 883 мс | DeepSeek ToU |

Подробно — `local_benchmark_summary.json`, `cloud_benchmark_summary.json` (матрицы ошибок по классам).

**Наблюдения**

- Самая большая локальная модель (`seara`, 178 M) оказалась худшей: 3 из 4 негативных обращений она
  отнесла к нейтральным. Она обучена на отзывах и новостях, а у нас — жалобы на приложение; домен
  важнее размера.
- `mxlcw/...financial-sentiment` дообучена на финансовых текстах — лучшая локальная и самая быстрая.
- Облачные LLM точнее (+8 п. п.), но в ~500 раз медленнее и платные за каждый запрос; ошибки у них
  разные: Gemma приняла «работает, но не всегда точно» за негатив, DeepSeek — благодарность
  «понимаю, куда уходят деньги» тоже за негатив.
- **Облако не детерминировано даже при temperature=0:** DeepSeek в трёх прогонах дал 91,7 % → 83,3 % →
  91,7 %. Для тестов это значит: одной цифре верить нельзя, нужны повторы.
- Бесплатная `gemma-4-31b-it:free` весь вечер отвечала 429 (общий лимит у провайдера) —
  бесплатные модели не годятся для того, что должно работать всегда; взята платная (≈ $0,0003 за прогон).

**Лицензии.** `seara` и `mxlcw` — MIT (можно в коммерческом дипломном продукте). У `cointegrated`
лицензия в карточке не указана — юридически это «все права защищены», для продукта её брать нельзя
без разрешения автора, даже если в учебном проекте она работает.

**Вывод.** Для классификации тональности в продукте — `mxlcw/rubert-tiny2-russian-financial-sentiment`
локально: 83 % при 1,4 мс, без сети и без оплаты за запрос, MIT. Облачную LLM имеет смысл звать только
для «сомнительных» случаев (низкая уверенность локальной модели) — так получаем точность ближе к 92 %
почти без затрат. Она же — в Gradio-демо (`gradio_demo.py`).

**Gradio-демо.** Локально работает (`http://127.0.0.1:7860`, скриншот — `gradio_demo.png`, три запроса через
API — `gradio_predictions.txt`). Публичная ссылка `*.gradio.live` на этой машине не создаётся: Windows
Defender удаляет туннель Gradio (`frpc_windows_amd64`) как HackTool — известное ложное срабатывание.
Варианты: исключение в Defender для этого файла или постоянный хостинг на HuggingFace Spaces.
В демо видна и ошибка модели: «Спасибо, отчёт по категориям очень помог сократить траты» → neutral
(0,80) — благодарность без явно эмоциональных слов модель часто считает нейтральной.
